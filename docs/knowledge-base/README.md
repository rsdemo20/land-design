# База знаний: планировщик дачного участка

## 1. Назначение

Приложение помогает собрать исходную 3D-схему дачного участка и сравнивать
варианты размещения построек, инженерных объектов и растений. Это эскизный
планировщик, а не замена геодезическому, санитарному или строительному проекту.

Основной пользователь — владелец участка. Он задаёт неизменяемую основу в
режиме «Создание участка», а затем работает с несколькими вариантами в режиме
«Дизайн».

## 2. Стек

| Часть | Технология |
|---|---|
| Язык | Python 3.10 |
| 3D-интерфейс | Ursina 7.0.0 |
| 3D-движок | Panda3D 1.10.16, устанавливается как зависимость Ursina |
| Хранение | локальный UTF-8 JSON (`data.json`) |
| Тесты | стандартный `unittest` |
| Целевая среда | Windows 10, PowerShell, активированное `.venv` |

Установка и запуск:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main_3d.py
```

## 3. Простая архитектура

Проект остаётся монолитным настольным Python-приложением. Отдельный сервер и
база данных сейчас не нужны.

| Слой | Файлы | Ответственность |
|---|---|---|
| Данные предметной области | `core/domain.py` | участок, объекты, размеры, цвета, варианты дизайна и проверки целостности |
| Сценарии редактирования | `core/editor.py` | добавить, изменить, переместить, защитить, скрыть или удалить объект |
| Геометрия | `core/geometry.py` | площадь, контуры и проверка размещения внутри участка |
| Хранилище | `core/ports.py`, `core/json_repository.py` | контракт хранилища, чтение и атомарная запись JSON |
| Представление | `main_3d.py`, `main.py` | Ursina-интерфейс, ввод мышью/клавиатурой и отрисовка |
| Проверки | `tests/test_core.py` | поведение ядра и совместимость JSON |

Поток данных: пользователь меняет объект в интерфейсе → `ProjectEditor`
проверяет действие → доменные модели обновляются → репозиторий атомарно
перезаписывает `data.json` → интерфейс перерисовывает сцену.

Архитектурное правило проекта: `core/` не импортирует Ursina. Визуальные детали
должны оставаться в `main_3d.py`/`main.py`, а правила данных и редактирования — в
ядре, где их можно проверить без запуска окна.

## 4. User stories

- Как владелец участка, я хочу зафиксировать границы, заборы, ворота, колодец,
  дорогу и соседние объекты, чтобы получить узнаваемую основу схемы.
- Как владелец участка, я хочу создавать несколько дизайнов и переключаться
  между ними, чтобы сравнивать варианты без потери предыдущего.
- Как пользователь, я хочу добавлять типовые строения, примитивы и растения,
  чтобы быстро собирать план без 3D-моделирования.
- Как пользователь, я хочу перемещать, поворачивать и менять размеры и цвета
  выбранного объекта, чтобы подгонять схему под реальные размеры.
- Как пользователь, я хочу видеть сетку и координаты проекции курсора, чтобы
  размещать объекты в метрах.
- Как пользователь, я хочу защищать важные объекты от случайного изменения и
  удаления.
- Как пользователь, я хочу редактировать окружение только в режиме «Создание
  участка», чтобы в режиме «Дизайн» случайно не сдвинуть исходную обстановку.
- Как пользователь с большим архивом, я хочу искать, фильтровать и сортировать
  сохранения, чтобы быстро находить нужный вариант среди сотен схем.

## 5. Требования

### Функциональные

- `FR-01` — хранить участок, окружение, объекты и дизайны в одном версионируемом
  JSON-файле.
- `FR-02` — поддерживать режимы «Создание участка» и «Дизайн» с разными
  правилами редактирования.
- `FR-03` — создавать куб, цилиндр, параллелепипед, дугу, типовые строения,
  деревья, кусты и грядки.
- `FR-04` — редактировать положение X/Z, поворот, размеры X/Y/Z, вариант,
  основной и дополнительный цвета.
- `FR-05` — в режиме «Дизайн» не позволять объекту выходить за границы участка;
  в режиме «Создание участка» разрешать окружение за границей.
- `FR-06` — защищать объект от перемещения и удаления; стационарный объект после
  снятия защиты скрывать в выбранном дизайне, а не уничтожать из исходника.
- `FR-07` — автоматически сохранять текущий дизайн перед переключением на
  другой.
- `FR-08` — показывать координатную сетку с шагом 2 м, оси, начало координат,
  направление севера и координаты точки под курсором.
- `FR-09` — сохранять данные атомарно и читать старые поддерживаемые версии
  схемы JSON.

### Нефункциональные

- `NFR-01` — основной сценарий должен работать локально на Windows 10 без
  сетевого сервиса.
- `NFR-02` — единицы геометрии в модели — метры; поверхность участка считается
  ровной.
- `NFR-03` — ядро не зависит от Ursina и проверяется обычными unit-тестами.
- `NFR-04` — неизвестная или некорректная запись JSON должна давать понятную
  ошибку, а не частично портить файл.
- `NFR-05` — интерфейс должен оставаться пригодным для работы как минимум с
  сотнями сохранённых дизайнов; для этого нужны поиск, фильтры и ленивое
  отображение списка.
- `NFR-06` — визуальные слои на одной высоте не должны заметно мерцать при
  движении камеры.

## 6. Состав версий

Версии ниже восстановлены из локального каталога `saves/`. Номер продуктового
снимка не равен `schema_version` внутри JSON.

| Версия | Состав |
|---|---|
| v1 — `plot-layout_v1` | исходные размеры участка, ворота и калитки, колодец, короткий заезд, три варианта планировки, плоская схема и 4 теста |
| v2 — `plot-layout_v2_3d` | 3D-редактор, перемещение по плоскости, поворот, примитивы и независимое от Ursina ядро редактирования |
| v3 — `plot-layout_v3_typical-objects` | режимы «Создание участка»/«Дизайн», типовые объекты, защита, удаление и скрытие |
| v4 — `plot-layout_v4-coordinate-grid` | координатная сетка, координаты X/Z, природные объекты и варианты растений |
| v5 — `plot-layout_v5-arc-primitives` | дуга с кривизной, материалы дуги, редактируемое окружение, дорога и канава |
| v6 — `plot-layout_v6-photo-trees-protection` | фотореалистичные сосна, берёза и ясень; защита действительно блокирует перемещение, а колодец и туалет двигаются после снятия защиты |
| Текущая рабочая версия | второй цвет объекта, 16-цветная палитра с ручным HEX, двускатные крыши бани/сарая, односкатная крыша гаража, миграция JSON и проектная документация |

Каталог `saves/` остаётся локальным архивом и исключён из новых коммитов. Его
состояния представлены последовательными коммитами Git, поэтому историю можно
смотреть и сравнивать обычными командами `git log` и `git diff`.

## 7. Roadmap

Roadmap — список намерений, а не обещание сроков. Приоритет уточняется перед
каждым новым этапом.

### Ближайшие улучшения

- Убрать мерцание при наложении почти совпадающих слоёв (z-fighting), прежде
  всего у дороги, площадок и верхних текстур: задать единые уровни слоёв и
  минимальные вертикальные смещения.
- Добавить отмену/повтор действий и дублирование объекта, чтобы ошибки в
  редакторе были обратимыми.
- Сделать редактор объектов удобнее: единый инспектор свойств, явная кнопка
  применения, валидация рядом с полем, выбор цвета, точный ввод координат и
  блокировка пропорций.
- Подготовить работу с сотнями сохранений: строка поиска, фильтры по тегам и
  дате, сортировка, избранное/архив, пагинация или виртуальный список.

### Следующий этап

- Расширить библиотеку объектов: теплица, навес, беседка, парковка, дорожки,
  клумбы, крупные деревья, коммуникации и условные санитарные зоны.
- Добавить привязку к сетке, направляющие, измерение расстояний и подсветку
  пересечений объектов.
- Добавить миниатюру, описание, теги и время изменения для каждого дизайна;
  предусмотреть экспорт/импорт одного дизайна.
- Разделить крупный `main_3d.py` на небольшие модули представления: сцена,
  инспектор, панель объектов и управление камерой — без усложнения ядра.

### Позже

- Редактор составных типовых объектов: стены, крыша, двери, окна и материалы.
- Рельеф и уклон участка как опциональный режим.
- Автоматические резервные копии, восстановление повреждённого сохранения и
  миграции между версиями JSON с отчётом пользователю.
- Печать/экспорт плана с размерами и перечнем объектов.

## 8. Готовность изменения

Изменение считается завершённым, когда данные сохраняются и повторно
загружаются, старый JSON остаётся совместимым либо мигрируется, проверки ядра
проходят командой ниже, а заметное изменение интерфейса проверено запуском 3D-
редактора на Windows:

```powershell
python -m unittest discover -s tests -v
```
